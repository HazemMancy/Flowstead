# Decisions

The owner asked me to make the open calls from `docs/PLAN.md` §8 myself. Each
one is recorded here so it can be revisited. Entries marked **(hard to
reverse)** are the ones to look at first.

| # | Question | Decision | Why |
|---|---|---|---|
| D1 | Engine binaries | Official DWSIM 9.0.5 linux-amd64 package (SHA-256 pinned) now; add a Windows CI job that builds the engine DLLs from the pinned submodule later | Fastest path to a working engine. Same assembly version as the pinned commit. GitHub release downloads are blocked from the dev sandbox; SourceForge is not. |
| D2 | Pin | `1abf72d1b6b4…` (DWSIM 9.0.5.0, 2026-07-17), the last commit on the default branch (`windows`) | Matches the 9.0.5 release. Archive status not verifiable from the sandbox (GitHub API blocked). |
| D3 | "Peng-Robinson (Lee-Kesler)" | DWSIM's **PR/LK** (`PengRobinsonLeeKesler.vb`: PR EOS for phase equilibria, Lee-Kesler for enthalpy/entropy). We register it ourselves, because `Automation3` doesn't. | That's what the name describes. LKP is a different package and stays available as an extra. |
| D4 | Auth **(hard to reverse)** | Per-device API keys. Admin issues them with `flowstead-engine keys add <device>`. Only a SHA-256 hash is stored server-side. The app keeps the key encrypted with an Android Keystore AES-GCM key. HTTPS is done by a reverse proxy (Caddy) in front of the engine. | Self-hosted, single owner or small team. No user directory to manage. Easy to revoke per device. |
| D5 | Data model **(hard to reverse)** | Flowstead's own JSON flowsheet model (`shared/schema/flowsheet.schema.json`) is the master copy. `.dwxmz` is import/export only. | The phone needs to edit, diff, validate and render offline without DWSIM. |
| D6 | Benchmark expected values | Each `expected.json` records its `source`. Values produced by our own engine are marked `"source": "engine-provisional"` and replaced when desktop-DWSIM or HYSYS/UniSim numbers arrive. HYSYS numbers go in a non-blocking `reference` block. | Avoids pretending a self-generated value is independent verification. |
| D7 | Hosting arch | linux-x64 only | `libCoolProp.so`, `libIpopt39.so` and SkiaSharp ship x64-only in the DWSIM package. |
| D8 | Our licence **(hard to reverse)** | GPL-3.0-or-later | Same terms as DWSIM's own headers. Keeps the option of later GPL versions. |
| D9 | Units | Atmospheric reference for barg defaults to 101.325 kPa, stored per project (Settings sets the default for new projects). Standard volume: Sm³ at 15 °C / 101.325 kPa; MMSCF at 60 °F / 14.696 psia. | Matches common O&G practice and HYSYS defaults. A per-project reference handles sites at altitude. |
| D10 | Application ID **(hard to reverse)** | `app.flowstead` | Short and brand-led. Change it before the first Play Store upload if the domain isn't available. |
| D11 | Separator palette | Two palette items, "Separator" (2-phase) and "3-Phase Separator", both map to DWSIM `Vessel` | HYSYS engineers look for two icons. The engine object is the same. |
| D12 | Engine concurrency | Worker pool of child processes, one solve per process at a time, hard kill on timeout | DWSIM keeps process-wide static state, and its cancellation is cooperative. |
| D13 | Android HTTP client | Ktor client + kotlinx.serialization | One serializer end to end. Shares DTOs with the pure-Kotlin `:core` module. |
| D14 | Value colours vs 4.5:1 contrast | The brief's under-specified `#B7791F` (3.6:1 on white) and converged `#1F8A4C` (4.4:1) are used unchanged for swatches, badges and borders (3:1 is enough there). Text uses darker variants: `#8F5E12` (5.6:1) and `#19763F` (5.7:1). `ContrastTest` enforces this. | The brief asks for both the exact colours and ≥ 4.5:1 text contrast, so the two can't both apply to text. |
| D15 | Android toolchain | AGP 9.4.1 with built-in Kotlin (no `kotlin-android` plugin), Gradle 9.8.2, Kotlin 2.4.21, KSP 2.3.12, Hilt 2.60.1, Compose BOM 2026.09.00, compile/target SDK 37. Was AGP 8.11.1 / Kotlin 2.2.0 / SDK 36 until M9. | Google Maven can't be reached from the dev sandbox, so the first set was pinned to versions known to be released together. M9 moved to the latest stable versions from CI's `toolchain-report` job, verified in CI. |
| D16 | Engine TLS | App is HTTPS-only; it trusts user-installed CAs, so a LAN engine can use a private CA | Brief says HTTPS only. Self-signed certificates on a home or office network otherwise can't work. |
| D17 | Water + hydrocarbons | Cubic EOS (PR, SRK, PR/LK, GERG) with water and hydrocarbons uses DWSIM's immiscible-water (free-water) three-phase flash. Rigorous VLLE is used with polar solvents (glycols, alcohols, amines) or NRTL/UNIQUAC. The solver log says which. | Measured on benchmark 04: DWSIM's default flash and its rigorous PR VLLE both left 44 mol % water in a single "hydrocarbon" liquid, which is unphysical. The free-water flash gives 99.95 % water in the aqueous phase, as HYSYS does. |
| D18 | Recycle tolerances | 1e-6 kg/s, 1e-3 K, 1 Pa, 1e-6 composition, 100 iterations. The engine also checks the overall mass balance and warns above 0.01 %. | DWSIM's defaults (0.01 kg/s, 0.1 K) stopped benchmark 07 after 4 iterations with a 1.5 % open mass balance. Now it takes 18 iterations and closes to 8 ppm. |
| D19 | Adjust | Done in Flowstead's engine layer: secant steps, then bisection once bracketed, with each iteration a full DWSIM solve. One Adjust per flowsheet. Any spec can be varied and any result controlled, with optional bounds and tolerance. | Avoids DWSIM's internal property codes and unit systems. It is transparent and testable (verified against IAPWS: heater duty for VF = 0.5 water). |
| D20 | `.dwxmz` import/export | The engine does both. Export builds, solves and saves with DWSIM, so the file opens in desktop DWSIM with results. Import maps streams, unit ops, connections, positions, package and compounds. Any unsupported object or calculation mode is left out with a warning, and the app lists every warning before opening the project. The app sends and receives files as base64 JSON. Adjusts are not exported. Energy streams that the engine added become real energy streams after a round trip. | DWSIM's file format is only readable with DWSIM itself, so it has to happen on the engine. Silent loss would break "never show a number the engine did not return". Base64 JSON keeps the app on one serializer, with no multipart handling. |
| D21 | Results export | CSV and `.xlsx` are written on the phone from the stored solve, so they work offline. The `.xlsx` writer is ~150 lines over `java.util.zip` rather than Apache POI. Values have up to 10 significant figures in the user's units. A value the engine did not return is an empty cell. Stale results are labelled on every sheet. A leading `=`, `+` or `@` in user text is defused in CSV. | POI adds ~10 MB and needs desugaring on minSdk 26. The workbook needs only text and numbers. |
| D22 | Offline solve queue | A solve that fails because the engine is unreachable (no connection, as opposed to the engine refusing) is queued with WorkManager on a network constraint. Exponential backoff, up to 8 attempts. It solves the flowsheet as it is when the job runs, and is dropped if the flowsheet has become unsolvable. The solve bar shows "Queued" with Cancel. | The phone is often offline on site. Solving the latest flowsheet avoids storing a result for a model that no longer exists (results stay hash-checked either way). |
| D23 | Object model | Every unit op planned up to M17 is in the model and the schema now. `available` marks what the engine solves, and the palette shows the rest as "Coming". | The file format and palette are stable while unit ops land one group at a time. |
| D24 | Compound library on the phone | All 1,488 compounds DWSIM loads are bundled: ChemSep, ChEDL Thermo, CoolProp, electrolytes, food and DWSIM's own. They are exported by the engine (`engine/tools/compounds/build_catalogue.py`), with a Hill formula and a family added using RDKit. Search, filters and constants work offline. Licences: ChemSep under Artistic 2.0 (a converted subset, freely available here), ChEDL and CoolProp under MIT, DWSIM under GPL. | The user asked for a HYSYS-like component library regardless of app size. The engine solves with the same databases, so any compound found on the phone is one the engine knows. |
| D25 | On-device solving **(hard to reverse; owner's choice)** | DWSIM runs on the phone. The .NET Mono runtime is embedded in the app through a small C host and JNI, and runs the same `DwsimEngine` the server runs. Remote engines stay available. The GPU is not used: steady-state flowsheet solving is small sequential work (flashes, recycles, column stages) with no data-parallel kernel for a GPU to run. | The owner chose "Embed DWSIM in the app". The proof on Linux with Mono 8.0.32 gives results bit-identical to the server on all 8 benchmarks, so on-device results stay DWSIM's results. |
| D26 | Separators and logic (M15): how each maps to DWSIM, and where it differs from HYSYS | **Set:** applied by Flowstead before every solve and every Adjust iteration (target = multiplier × source + offset, chains allowed, loops refused). It is not written to `.dwxmz`. **Air cooler:** a DWSIM cooler on the process side. There is no fan or air-side model, unlike the HYSYS Air Cooler. **Tank:** a flash vessel. With a volume, it reports the liquid residence time. **Component splitter:** DWSIM's component separator. Both products leave at the feed T and P, and the duty to hold them there is reported. **Filter, solids separator, energy recycle:** stay "Coming". The first two need solids characterisation. DWSIM's energy recycle opens a WinForms dialog when it hits its iteration limit, which would crash a headless engine. | Same reasons as D19 for doing the logic in Flowstead. DWSIM's own Air Cooler 2 is a separate plugin that is not in the engine bundle. The differences from HYSYS are stated in the editors. |
| D27 | Columns (M16) | **Model:** HYSYS-style. Theoretical trays from the top, condenser and reboiler not counted. A tray number per feed. Top pressure and column ΔP. One condenser spec (reflux ratio, distillate rate, distillate mole fraction or recovery) and one reboiler spec (boil-up ratio, bottoms rate, reboiler duty, bottoms mole fraction or recovery). The engine wires it through DWSIM's column API. The default solver is Wang-Henke; the other DWSIM solvers can be picked. **Check:** after each solve, every rigorous column is compared with its own specs and with its mass and energy balances. A miss makes the column, and everything downstream of it, an error with the reason; no numbers are shown. **Left out, as differences from HYSYS:** condenser duty and stage-temperature specs, and the refluxed absorber. Filter and solids separator remain "Coming". | Tested on a depropanizer across eight spec pairs. Naphtali-Sandholm converged less often than Wang-Henke, and once stopped short of its spec. Duty and temperature specs mostly failed. Condenser duty + bottoms rate "converged" with zero reflux, and only the specs could have caught it. The refluxed absorber's condenser duty is (RR + 1) times what its own energy balance needs. DWSIM's absorber `ConnectTopProduct` files the top product as liquid distillate; the engine re-files it as overhead vapour. |
| D28 | Water flash and IPOPT (found while adding reactors) | **Free water (amends D17):** DWSIM's free-water flash is used only when every stream stays at or below 150 °C and every stream's phase fractions add up to 1. Otherwise the engine re-solves the whole flowsheet with the standard flash, and the solver log says so. **IPOPT:** not shipped. `engine/native/ipopt_stub.c` provides `libIpopt39` for the server, Docker and Android, and reports "Internal_Error", which DWSIM treats as an ordinary non-convergence. The Gibbs-minimisation flash uses DWSIM's managed L-BFGS. | Measured on methane, n-hexane and water at 20 bar. Free water gave all-liquid at 300 °C, phase fractions summing to 1.18, an enthalpy of −719 MJ/kg, and a 7 % enthalpy error even when the stream was all vapour at 200 °C. Without any `libIpopt39`, a DWSIM path that reached IPOPT (NRTL with water) crashed the worker from a finalizer, which no handler can catch; on the phone that would close the app. |
| D29 | Reactors (M17) | Reactions belong to the flowsheet; each reactor ticks the ones it runs. Conversion reactions: constant conversion of a base reactant. Equilibrium reactions: K from Gibbs energies of formation, vapour (fugacity in bar) or liquid (activity); "mixture" is refused. Kinetic reactions: Arrhenius, rate in mol/(m³·s), concentrations in mol/m³. Gibbs reactor: no reactions, DWSIM's managed minimiser. After the solve, every reactor's mass balance is checked, and a conversion reactor must reach its conversion. | DWSIM's equilibrium reactor hung for 90 s on a mixture-phase basis, and failed with "negative mole fractions" on fugacity without units. The Gibbs reactor needs its element matrix built as DWSIM's editor does, and IPOPT switched off. Benchmarks 13–15 check stoichiometry, the Moe water-gas-shift correlation, agreement between the equilibrium and Gibbs reactors, and the first-order CSTR and PFR design equations. |
| D30 | Line sizing (M18) | **Sizes:** NPS 1/8–36 with walls from ASME B36.10M and B36.19M, written into Flowstead (`PipeSizes.kt`); choosing a size and schedule sets the inside and outside diameters; "custom" keeps a typed inside diameter. **Flow models:** single phase is DWSIM's Darcy–Weisbach (Chen, Churchill in transition) in every case, re-evaluating properties increment by increment; the two-phase correlation is chosen (Beggs & Brill by default). **Results:** from DWSIM's increment profile: mixture (superficial gas + liquid) velocity at inlet, outlet and maximum, ρv² with the no-slip density, total and frictional ΔP per length, Mach number, mean holdup and flow regimes. **Criteria:** the user's own limits per service (gas, liquid, two-phase), stored with the flowsheet but outside the model hash; none are pre-filled. API RP 14E is checked as ρv² ≤ C² lb/ft·s², which is the same as v ≤ C/√ρ at every point. | DWSIM's own pipe table has typos (e.g. NPS 1 STD wall 0.140 in instead of 0.133; NPS 5 10S ID 5.925 instead of 5.295); its inside-diameter column otherwise agrees with Flowstead's table on 273 entries. Company limits differ, so Flowstead ships none rather than inventing defaults. |
| D31 | Equipment data sheets (M19) | A PDF or Excel data sheet per piece of equipment, carrying the Flowstead logo and name (owner's choice) (every unit operation; not streams or logical blocks), drawn on the phone with Android's `PdfDocument`, A4. Layout: a title block on every page (company, title, tag, doc. no., rev., date, sheet n of m; project, project no., client, site; service, units, prepared, checked, approved), then numbered lines in gridded sections: general, operating conditions (one column per connected stream, with vapour/liquid/aqueous blocks), design basis (the user's inputs), performance (the engine's results), line sizing (pipes), reactions, composition, mechanical/design data (free text, blank boxes when empty), notes and a revision block. The title-block details belong to the project; doc. no., rev., service, design data and notes to each equipment; both are stored with the flowsheet outside the model hash. "All equipment" makes one PDF. | Process numbers on the sheet are the engine's, as everywhere else ("—" when not returned); the notes say so. Mechanical design (design P/T, materials, codes) is not simulated, so those lines are the user's text or left blank to complete by hand, as is usual on a process data sheet. |
| D32 | Liquid density with cubic EOS (found while sizing two-phase lines) | PR, SRK and PR/LK keep DWSIM's default liquid density (pure-component experimental correlations, mixed by volume) except when more than 1 mol % of the liquid is above its critical temperature; then COSTALD, the HYSYS method for hydrocarbon liquids, is used for that phase. Implemented as Flowstead subclasses of DWSIM's three packages (`LiquidDensity.cs`). Exported `.dwxmz` files keep DWSIM's own classes, so desktop DWSIM opens them; the export notes that liquid densities may differ. Benchmark 17 guards it. | DWSIM's default gives a component above its critical temperature a density of 10²⁰ kg/m³, so dissolved methane had mass but no volume: a C1/C2/C3 liquid at −40 °C read 742 kg/m³ (COSTALD 483; pure propane 581), and the lean-oil absorber's rich oil 833 kg/m³, above pure n-decane (726). Measured against NIST/IAPWS: the default is within 0.3 % for propane, n-hexane and n-decane and 0.1 % for water; COSTALD is within 0.3 % for the hydrocarbons but 1 % high for water; PR's own EOS volume is 15 % low for water. Two-phase pipe ΔP and tank residence times move with it. |
